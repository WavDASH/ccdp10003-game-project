# Core Time-Play Replay Viewer

A two-mode showcase for the Project 1.2 proposal website.

- **Authoring mode** — used inside Godot to *record* the demo.
- **Playback mode** — exported to HTML and embedded on the website. Viewers only see playback controls (play/pause/reverse/restart/scrub).

The website viewer **never controls the player** and **never solves the puzzle live**. The replay is captured ahead of time by us and stored in a `.tres` resource that ships with the web build.

---

## Files

| Path | Purpose |
|---|---|
| `scripts/web_showcase/showcase_replay_data.gd` | `class_name ShowcaseReplayData` — Resource holding `frames` and `markers` |
| `scripts/web_showcase/showcase_recorder.gd` | Authoring-only Node. F9/F10/F11/F8 hotkeys |
| `scripts/web_showcase/recording_stage.gd` | Authoring scene root. Stripped mirror of `main.gd` |
| `scripts/web_showcase/showcase_replay_viewer.gd` | Web-mode root. Loads the `.tres` and drives all visuals |
| `scenes/web_showcase/showcase_room.tscn` | The puzzle layout used for recording |
| `scenes/web_showcase/core_time_play_recording_stage.tscn` | The authoring scene (run inside Godot) |
| `scenes/web_showcase/core_time_play_replay_viewer.tscn` | The web/viewer scene (export this to HTML) |
| `data/web_showcase/core_time_play_replay.tres` | Generated by F10 — the demo recording |

The main game (`main.tscn`, prototype rooms, all gameplay scripts) is **untouched**.

## Recording a new replay

1. Open `scenes/web_showcase/core_time_play_recording_stage.tscn` in Godot 4.6 and press **F6** to play it.
2. The puzzle room loads with one player + two switches + one door (door requires both switches). A status bar at the top shows the recorder hotkeys.
3. Press **F9** — the bar turns red and shows live frame/marker counts.
4. Play out the demo using the normal game controls:
   - Walk to **Switch A** (A/D + Space). Press **F8** to drop a `Record Action` marker as you step on it.
   - Press **R** to reverse. Press **F8** for `Rewind`.
   - When the **Echo** appears, press **F8** for `Echo Appears`.
   - Walk to **Switch B**. Press **F8** for `Cooperate`.
   - When the **door opens**, press **F8** for `Door Opens`.
5. Press **F10** — saves to `res://data/web_showcase/core_time_play_replay.tres`. The console prints `[ShowcaseRecorder] saved N frames (Xs) → ...`.

If you want to throw out a take mid-record, press **F11**.

The first F8 press always inserts the **`Start`** marker, so feel free to press F8 the moment you press F9 to anchor t=0.

> **Tip:** marker labels cycle through `Start → Record Action → Rewind → Echo Appears → Cooperate → Door Opens` in order. If you press F8 too many times the last label sticks. You can rename or delete markers later by editing the `.tres` in a text editor — they're a plain `Array` of `{"t": float, "label": String}`.

### Captions on the website

Captions are mapped from marker labels in `showcase_replay_viewer.gd` (constant `CAPTIONS`). Use exactly these labels, or extend the dictionary if you add custom ones.

## Previewing the replay

1. Open `scenes/web_showcase/core_time_play_replay_viewer.tscn` and press **F6**.
2. The viewer auto-loads `res://data/web_showcase/core_time_play_replay.tres`.
3. Use the bottom controls to play, pause, reverse, restart, or scrub. There is no keyboard control.
4. If no replay file is found, an overlay tells you to record one first.

The viewer scene **does not load any game systems**. All switch/door/echo states come straight from the recorded frame data — no live collision recomputation.

## Exporting for the web

This is documented setup; we do not auto-modify `export_presets.cfg`.

1. **Project → Export → Add… → Web** (HTML5).
2. Name the preset: `Web Proposal Core Time Play`.
3. **Main Scene**: `res://scenes/web_showcase/core_time_play_replay_viewer.tscn`.
4. **Resources** tab → ensure `data/web_showcase/core_time_play_replay.tres` is included (default behavior is to include all referenced resources, but verify).
5. Optional: in **Features**, exclude unused (this scene only uses Polygon2D / Label / OptionButton / HSlider / HBoxContainer).
6. **Export Path**: e.g. `build/web_showcase/index.html`.
7. Click **Export Project**.

### Recommended Project Settings overrides for this preset

You can either set these globally (affects all run modes) or use the per-preset override system in Godot:

```
display/window/size/viewport_width = 1280
display/window/size/viewport_height = 720
display/window/stretch/mode = canvas_items
display/window/stretch/aspect = keep
```

### Embedding on the website

Drop the exported `index.html`, `index.js`, `index.wasm`, and `index.pck` into a folder, e.g. `public/godot/core_time_play/`, then embed:

```html
<iframe
  src="/godot/core_time_play/index.html"
  width="1280" height="720"
  style="border: 0;"
  allow="cross-origin-isolated">
</iframe>
```

The `cross-origin-isolated` permission and the `Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp` HTTP headers may be required for SharedArrayBuffer support in some Godot 4 web builds. Test locally first using `python -m http.server` (which doesn't set those headers) — if Godot complains, add them to your hosting layer.

## What runs where

| Component | Authoring (in Godot) | Playback (web) |
|---|---|---|
| `TimelineManager` | ✅ active | ❌ not present |
| `ActivePlayer` (movement/physics) | ✅ active | ❌ not present |
| Production switches/door (`SwitchTrigger`, `DoorReceiver`) | ✅ active | ❌ not present |
| `EchoPlayer` (replay) | ✅ active | ❌ not present |
| `ShowcaseRecorder` | ✅ samples scene state | ❌ not present |
| `ShowcaseReplayData` (.tres) | written | read-only |
| `ShowcaseReplayViewer` + visual stand-ins | ❌ | ✅ |

This split means: when the website iframe loads, **no gameplay logic runs**. The viewer reads the resource and tweens visuals. That makes the demo deterministic, lightweight, and safe to embed.

## Demo-only behaviors (worth knowing if editing)

- The recorder samples only **`echo_instances[0]`** — the showcase has at most one echo. If you add more reversals while recording, only the first echo is captured.
- The replay viewer has no physics; the door's "opening" is purely visual (alpha fade + Y-scale collapse).
- Caption text is keyed by the **exact marker label string**. Misspell a label in the `.tres` and the caption goes blank — the viewer fails open rather than crashing.
- Playback automatically pauses when reaching either end. Press Play to loop back to the start.

## Troubleshooting

- **"No replay loaded" overlay** — the `.tres` doesn't exist or is empty. Run the recording stage and press F9 → F10.
- **F10 prints `save to res:// failed`** — Godot is enforcing read-only `res://`. The recorder falls back to `user://core_time_play_replay.tres` and prints the location. Move that file into `res://data/web_showcase/` from your OS file manager.
- **Markers don't appear on the timeline strip** — that strip is sized at scene load. If your replay has 0 duration the strip stays empty.
- **Web build won't load** — ensure your hosting serves `.wasm` with MIME `application/wasm` and supports gzip/br for the `.pck`.
